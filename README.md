# Вайб: конкурсная версия

«Вайб» — школьная платформа с заданиями, прогрессом, внутренней валютой, маркетом и четырьмя ролями. Это отдельная конкурсная копия: она использует собственную SQLite и собственные загрузки, не подключается к базе действующего сайта [vaibe32.ru](https://vaibe32.ru).

Работа и проверка продолжаются. Репозиторий и контейнер пока не следует считать готовыми для конкурсной подачи.

## Быстрый запуск

Нужны Docker Engine с плагином Docker Compose и свободный локальный порт 3101. В каталоге репозитория:

```sh
docker compose build
docker compose up -d --wait
```

Откройте http://127.0.0.1:3101. Для проверки доступны четыре синтетических профиля: ученик, учитель, администратор школы и владелец проекта. Вход осуществляется кнопками на стартовой странице, без реальных учётных записей и MAX-токена.

Сборка загружает npm-зависимости и базовый образ из сети; работа запущенного приложения и файлы документов не зависят от production-сервера. Порт привязан только к локальному интерфейсу. Этот образ предназначен для демонстрации, не для публичного развёртывания: он включает вход без пароля.

## Готовый образ в GHCR

Приватный образ: `ghcr.io/vibe-platform/vibe-school-platform:contest`. Для доступа нужны права на пакет и вход Docker в GHCR с учётными данными GitHub, имеющими право `read:packages`.

```sh
docker login ghcr.io
docker pull ghcr.io/vibe-platform/vibe-school-platform:contest
docker run -d --name vibe-contest -p 127.0.0.1:3101:3101 -v vibe-contest-data:/app/data ghcr.io/vibe-platform/vibe-school-platform:contest
```

Эти команды загрузки и запуска образа пока не проверены отдельно; проверенный вариант запуска из исходников приведён выше. Образ предназначен для локальной демонстрации.

## Сохранение данных

При первом старте миграции создают отдельную базу, затем в неё добавляются тестовая школа, четыре профиля и разрешённое содержимое. Оригиналы документов и изображений распаковываются в отдельный том Docker. Повторный запуск не сбрасывает базу.

```sh
docker compose ps
docker compose logs -f
docker compose restart
docker compose up -d --force-recreate --wait
docker compose down
```

Том `vibe-data` сохраняется после `docker compose down`. Команда `docker compose down -v` удаляет только тома этого Compose-проекта и полностью сбрасывает его демонстрационные данные; применяйте её, лишь если они больше не нужны.

Изменить порт можно, задав переменную `VIBE_PORT`, например:

```sh
VIBE_PORT=3201 docker compose up -d --wait
```

## Перенесённое содержимое

Отобраны опубликованные разделы «Документы», «Сотрудничество», «О нас» и FAQ, а также активный глобальный каталог и учебные задания. Включены четыре PDF, шесть партнёров и 54 связанных изображения, а также изображения раздела «О нас» и товаров. Контрольные суммы 77 файлов хранятся в `contest-assets/manifest.sha256`. Исходные аккаунты, ответы, оценки, заказы, пользовательские загрузки и production-база не включены.

Публичные данные и изображения договоров проверены перед включением; технические секреты и файлы конфигурации сервера не являются частью набора. Ссылки на внешние сайты и Яндекс Карты сохраняются как внешние ссылки.

## Технологии и зависимости

Node.js 22, React, TypeScript, Vite, Fastify, Prisma и SQLite. Точные npm-версии зафиксированы в `package-lock.json`. Проект не использует Python-зависимости; `requirements.txt` поясняет это для конкурсной заявки. Исходный MAX-бот указан отдельно: https://max.ru/ideya_fiks_75_bot. В контейнере реальная интеграция MAX отключена; вход в MAX и доставка сообщений внутри мессенджера требуют отдельной проверки.

## Проверки

Workflow `.github/workflows/contest-ci.yml` выполняет проверки исходников, сборку и запуск контейнера, проверку тестовых профилей и файлов после пересоздания контейнера, а также браузерные сценарии. Результаты конкретного запуска смотрите во вкладке Actions. Образ публикуется в приватный GHCR после успешных проверок; результаты отдельных запусков могут отличаться.

Логи и диагностика:

```sh
docker compose ps
docker compose logs --tail=100
docker compose down
```

Если порт занят, задайте другой `VIBE_PORT`. При ошибке сборки проверьте доступ к Docker Hub и npm. При проблеме запуска сохраните логи перед сбросом тома.
