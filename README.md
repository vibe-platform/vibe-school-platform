# Вайб: конкурсная версия

«Вайб» — школьная платформа с заданиями, прогрессом, внутренней валютой, маркетом и четырьмя ролями. Это отдельная конкурсная копия: она использует собственную SQLite и собственные загрузки, не подключается к базе действующего сайта [vaibe32.ru](https://vaibe32.ru).

## Быстрый запуск

Нужны Docker Engine с плагином Docker Compose и свободный локальный порт 3101. В каталоге репозитория:

```sh
docker compose build
docker compose up -d --wait
```

Откройте http://127.0.0.1:3101. Для проверки доступны четыре синтетических профиля: ученик, учитель, администратор школы и владелец проекта. Вход осуществляется кнопками на стартовой странице, без реальных учётных записей и MAX-токена.

Сборка загружает npm-зависимости и базовый образ из сети; работа запущенного приложения и файлы документов не зависят от production-сервера. Порт привязан только к локальному интерфейсу. Этот образ предназначен для демонстрации, не для публичного развёртывания: он включает вход без пароля.

## Как жюри проверить задание и оценку

Нажмите «Тест» на стартовом экране. Профили относятся к одной отдельной тестовой школе и классу:

- «Пользователь 1» — ученик.
- «Пользователь 2» — учитель.
- «Пользователь 3» — школьный администратор.
- «Пользователь 4» — владелец проекта.

1. Войдите как учитель, откройте раздел учителя, нажмите «Создать работу», заполните задание и вопросы, выберите класс 7A и нажмите «Опубликовать работу».
2. Завершите сеанс и войдите как ученик. Откройте опубликованное задание в списке заданий, выполните его и отправьте ответ. В зависимости от типа задания можно приложить фотографию.
3. Вернитесь в профиль учителя и проверьте отправленную работу. Для вопросов, требующих проверки, выставьте оценку и при необходимости оставьте комментарий.
4. Снова войдите как ученик и посмотрите результат, EXP и баланс Эйнштейнов. Автоматически проверяемые вопросы могут получить результат сразу; ручная проверка требует действий учителя. Награда рассчитывается правилами приложения; повторное открытие результата не должно начислять её повторно.

## MAX и юридическая информация

В контейнер намеренно не включены действующие токены и реальные аккаунты. Поэтому сообщение «MAX не подключён» в конкурсной копии ожидаемо: для проверки используйте кнопку «Тест». Сообщения и вход реального мессенджера в автономном образе не имитируются.

Действующая версия находится по адресу [vaibe32.ru](https://vaibe32.ru); у неё настроена интеграция MAX и используются её собственные аккаунты и данные. Ссылка на действующего бота: [MAX-бот](https://max.ru/ideya_fiks_75_bot).

Юридические сведения и страницы действующего сайта доступны в [разделе правовой информации](https://vaibe32.ru/legal), в том числе [сведения о владельце](https://vaibe32.ru/legal/owner), [политика обработки персональных данных](https://vaibe32.ru/legal/privacy) и [пользовательское соглашение](https://vaibe32.ru/legal/terms). Опубликованные файлы также доступны в разделе [«Документы проекта»](https://vaibe32.ru/documents). На действующем сайте проверено наличие заполненных публичных реквизитов.

В конкурсной базе юридические сведения независимы от production и могут быть неполными. Тестовый владелец может заполнить их в разделе «Юридическая информация»: изменения сохраняются только в томе конкурсной версии и никак не меняют действующий сайт. Сведения production не следует автоматически считать юридическими данными отдельного демонстрационного экземпляра.

## Готовый образ в GHCR

Публичный образ: `ghcr.io/vibe-platform/vibe-school-platform:contest`. Для скачивания вход в GitHub не требуется.

```sh
docker pull ghcr.io/vibe-platform/vibe-school-platform:contest
docker run -d --name vibe-contest -p 127.0.0.1:3101:3101 -v vibe-contest-data:/app/data ghcr.io/vibe-platform/vibe-school-platform:contest
```

Эти команды загрузки и запуска образа пока не проверены отдельно; проверенный вариант запуска из исходников приведён выше. Образ предназначен для локальной демонстрации.

## Сохранение данных

При первом старте миграции создают отдельную базу, затем в неё добавляются тестовая школа, четыре профиля и разрешённое содержимое. Оригиналы документов и изображений распаковываются в отдельный том Docker. Повторный запуск не сбрасывает базу.

```sh
docker compose ps
docker compose logs -f
docker compose restart
docker compose up -d --force-recreate --wait
docker compose down
```

Том `vibe-data` сохраняется после `docker compose down`. Команда `docker compose down -v` удаляет только тома этого Compose-проекта и полностью сбрасывает его демонстрационные данные; применяйте её, лишь если они больше не нужны.

Изменить порт можно, задав переменную `VIBE_PORT`, например:

```sh
VIBE_PORT=3201 docker compose up -d --wait
```

## Перенесённое содержимое

Отобраны опубликованные разделы «Документы», «Сотрудничество», «О нас» и FAQ, а также активный глобальный каталог. Задания при первом запуске отсутствуют: учитель может создать их самостоятельно. Включены четыре PDF, шесть партнёров и 54 связанных изображения, а также изображения раздела «О нас» и товаров. Контрольные суммы 77 файлов хранятся в `contest-assets/manifest.sha256`. Исходные аккаунты, ответы, оценки, заказы, пользовательские загрузки и production-база не включены.

Публичные данные и изображения договоров проверены перед включением; технические секреты и файлы конфигурации сервера не являются частью набора. Ссылки на внешние сайты и Яндекс Карты сохраняются как внешние ссылки.

## Технологии и зависимости

Node.js 22, React, TypeScript, Vite, Fastify, Prisma и SQLite. Точные npm-версии зафиксированы в `package-lock.json`. Проект не использует Python-зависимости; `requirements.txt` поясняет это для конкурсной заявки. Исходный MAX-бот указан отдельно: https://max.ru/ideya_fiks_75_bot. В контейнере реальная интеграция MAX отключена.

Логи и диагностика:

```sh
docker compose ps
docker compose logs --tail=100
docker compose down
```

Если порт занят, задайте другой `VIBE_PORT`. При ошибке сборки проверьте доступ к Docker Hub и npm. При проблеме запуска сохраните логи перед сбросом тома.
